# Career Snowflakes

Локальное desktop-приложение на Wails 3, Go и React для отслеживания профессионального развития. Диаграмма вдохновлена [Medium Engineering Growth Framework](https://medium.com/s/engineering-growth-framework); стартовые описания этапов написаны для этого проекта и свободно редактируются.

В MVP приложение работает с одним локальным документом. Это временное ограничение объёма MVP; дальнейшее развитие предполагает загрузку карьерных треков других людей.

## Запуск

Нужны Go 1.25+, Node.js 24 LTS, pnpm 11.3.0 и Wails 3 CLI. Версия Go-библиотеки Wails закреплена в `go.mod`; CLI можно установить соответствующей версии:

```sh
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-alpha2.119
pnpm --dir frontend install --frozen-lockfile
wails3 dev
```

На Windows нужен WebView2 Runtime. Если PowerShell блокирует `pnpm.ps1`, используйте `pnpm.cmd` вместо `pnpm`. Глобальную execution policy менять не требуется.

```sh
wails3 build
```

Windows-приложение появится в `bin/career-snowflakes.exe`. `wails3 dev` запускает Go и Vite совместно. Отдельный `pnpm --dir frontend dev` запускает только фронтенд: для данных и файловых диалогов требуется desktop-runtime Wails.

## Как пользоваться

- Выберите трек в списке или сегмент круга: справа появится описание этапа и примеры.
- Кнопка «Установить уровень» сохраняет достигнутый уровень вместе со всеми предыдущими этапами. Можно снизить уровень или сбросить прогресс конкретного трека.
- В диаграмме работают стрелки: влево/вправо переключают треки, вверх/вниз — этапы, Home/End — первый/последний этап. Tab переводит фокус между элементами интерфейса.
- В настройках меняются профиль, название схемы, направления, цвета, треки, уровни и примеры. Изменения остаются черновиком до нажатия «Сохранить изменения». Удаление и отмена правок требуют подтверждения.
- Импорт и экспорт через системные диалоги используют JSON. Экспорт включает схему, профиль и прогресс. Импорт заменяет текущую карту только после успешной проверки и записи. Для нескольких карт сохраняйте отдельные экспорты.

Начальная матрица содержит четыре направления, 16 треков и пять этапов в каждом. Прогресс начинается с нуля. Счётчики показывают число достигнутых этапов, начатых треков и процент освоения схемы. Корпоративные грейды и пороги Medium не переносятся: их смысл зависит от конкретной организации.

## Личная матрица разработчика

[career-snowflake.json](career-snowflake.json) — отдельная личная матрица для инженера, который создаёт, запускает и поддерживает полноценные проекты, понимает назначение продукта и организует командную работу. Она содержит 6 направлений, 27 треков и по 5 уровней в каждом треке. Описания и материалы для развития написаны на английском.

| Направление | Треков | Содержание |
| --- | --- | --- |
| Software Engineering | 5 | Алгоритмы, качество кода, тестирование, работа с AI, системное проектирование и архитектура |
| Web Platform | 6 | Вёрстка, JavaScript и TypeScript в браузере, браузерные API, доступность, безопасность и производительность веб-интерфейса |
| Backend Engineering | 6 | Go и Gin; Node.js и NestJS; серверные API и интеграции; базы данных и хранение; очереди и фоновые задачи; безопасность серверных приложений |
| Delivery & Operations — Доставка и поддержка | 4 | Инфраструктура и окружения; CI/CD и релизы; наблюдаемость; надёжность и устранение инцидентов |
| Team & Processes — Команда и процессы | 4 | Методологии и улучшение процессов; планирование и организация работы; построение и развитие команды; коммуникация и совместные решения |
| Product Engineering | 2 | Понимание продукта и требований; продуктовая аналитика и проверка гипотез |

Файл предназначен для импорта как самостоятельный документ. При первом запуске приложение создаёт встроенную начальную матрицу из `internal/career/default*.go`; личная матрица применяется через импорт JSON. Перед заменой текущей карты можно сохранить её экспорт вместе с прогрессом.

### Как читать практические уровни

В четырёх дополнительных направлениях — Backend Engineering, Delivery & Operations, Team & Processes и Product Engineering — каждый уровень описывает действия в реальном проекте. С уровнем растут сложность задач, количество освоенных практик и широта ответственности. Чтение материалов помогает развитию; самооценка опирается на выполненную работу и её результат. Например, резервное копирование включает проверенное восстановление, а продуктовая гипотеза — оценку того, помогло ли изменение пользователям.

Уровни накопительные внутри трека. Go и Node.js развиваются независимо, Gin и NestJS входят в соответствующие треки. Максимальный уровень во всех треках не является обязательным требованием к роли: матрица помогает выбирать личные приоритеты. Для командных треков нужна реальная совместная работа с участниками проекта; индивидуальная учебная имитация не заменяет этот опыт.

### Границы направлений

- **Backend Engineering** описывает реализацию и сопровождение серверных решений. Выбор архитектурного подхода рассматривается в System Design & Architecture. PostgreSQL, Redis и RabbitMQ служат практической основой для работы с данными и асинхронными задачами.
- **Delivery & Operations** объединяет запуск и поддержку: Linux и Docker, GitLab CI/CD, метрики, логи, трассировки, алерты и восстановление. На старших уровнях инфраструктурного трека предусмотрена работа с Terraform и Kubernetes в реальном проекте, а в CI/CD — доставка в эти окружения.
- **Team & Processes** рассматривает Agile, Lean, Scrum, Kanban и XP как подходы и практики для решения задач команды. Они не образуют последовательность уровней: рост определяется широтой применения и результатами улучшений процесса.
- **Product Engineering** связывает инженерные решения с назначением продукта, проблемами пользователей и ограничениями бизнеса или сервиса. Продуктовая аналитика оценивает использование и пользу изменений; наблюдаемость в Delivery & Operations помогает понять техническое состояние системы.

Общие определения направления, трека, уровня и прогресса находятся в [глоссарии](GLOSSARY.md).

## Хранение и формат

Go хранит документ в `os.UserConfigDir()/career-snowflakes/career.json`:

- Windows: `%APPDATA%/career-snowflakes/career.json`.
- macOS: `~/Library/Application Support/career-snowflakes/career.json`.
- Linux: `$XDG_CONFIG_HOME/career-snowflakes/career.json` или `~/.config/career-snowflakes/career.json`.

Первый запуск создаёт начальную карту. Запись выполняется через временный файл в том же каталоге с последующей заменой. Повреждённый существующий файл не перезаписывается; интерфейс показывает ошибку и путь. Для восстановления сначала сохраните его копию, затем исправьте файл или переместите его, чтобы приложение создало новую карту.

Минимальный импортируемый документ:

```json
{
  "version": 2,
  "profile": { "name": "My Profile", "role": "Software Engineer" },
  "schema": {
    "name": "My Career Matrix",
    "groups": [{
      "id": "engineering",
      "name": "Technology",
      "color": "aqua",
      "tracks": [{
        "id": "testing",
        "code": "QA",
        "name": "Testing",
        "description": "Confidence in product behavior",
        "resources": "- [Testing guide](https://example.com/testing)",
        "levels": [{
          "name": "Introduction",
          "description": "I verify common and edge-case scenarios.",
          "examples": ["Add a regression test before fixing a defect."]
        }]
      }]
    }]
  },
  "progress": { "testing": 0 }
}
```

Ограничения: 1–8 направлений, 1–32 трека суммарно, 1–8 этапов в треке; в каждом направлении нужен хотя бы один трек. Идентификаторы направлений и треков уникальны во всём документе и содержат 1–64 латинских букв, цифр, `-` или `_`. Код каждого трека уникален и содержит 2–3 заглавные латинские буквы. Названия — до 120 символов, описания — до 4000, примеры — до 20 строк по 1000 символов. Цвета: `red`, `green`, `yellow`, `blue`, `purple`, `aqua`, `orange`. Прогресс — целое число от 0 до числа этапов; неизвестные треки, поля и версии JSON отклоняются. Размер файла ограничен 2 MiB.

`resources` хранит Markdown со ссылками и материалами для развития по конкретному треку. Поле необязательное: при отсутствии используется пустая строка.

## Код

- `internal/career`: Go-модели, проверка документа, начальная матрица.
- `internal/storage`: загрузка, сохранение, импорт и экспорт файлов.
- `careerservice.go`, `dialogs.go`: тонкий Wails-сервис и системные диалоги.
- `frontend/bindings`: сгенерированный контракт Go → TypeScript; не редактируется вручную.
- `frontend/src/app` связывает экраны, навигацию, загрузку документа и тему приложения.
- `frontend/src/career/document` хранит последнюю подтверждённую Go версию документа и связывает фронтенд с Wails.
- `frontend/src/career/matrix-editor` содержит редактор матрицы, черновик и преобразования полей формы.
- `frontend/src/career/self-assessment` содержит диаграмму, список треков, карточку уровня и изменение прогресса.
- `frontend/src/shared/ui` содержит общие компоненты интерфейса.

Причины такого деления описаны в [ADR 0001](docs/adr/0001-career-development-context.md).

Правила файлового формата и проверка данных находятся на Go. Фронтенд управляет состоянием интерфейса, черновиком и отображением; обновляет сохранённую карту только после успешного ответа Go. Типы интерфейса выводятся из generated bindings; уточнение non-null коллекций на границе основано на нормализации Go.

После изменения методов или Go-моделей:

```sh
wails3 generate bindings -clean=true -ts -i
```

## Цвета и компоненты

`frontend/src/app/styles/globals.css` содержит всю [Gruvbox-палитру](https://github.com/morhetz/gruvbox), например `--gruvbox-dark0`, `--gruvbox-aqua-bright`, и семантические токены shadcn (`--background`, `--foreground`, `--primary`, `--border` и другие). Для направлений используйте `--track-aqua` или Tailwind `text-track-aqua`: оттенок автоматически меняется вместе с темой. Тёмная тема — по умолчанию; светлая задаётся классом `.light` на корневом элементе.

Вёрстка компонентов, их состояния и адаптивность задаются Tailwind utility-классами рядом с JSX. В `globals.css` остаются только импорты Tailwind, палитра и семантические токены темы — компонентных селекторов в нём нет.

Компоненты установлены официальным [shadcn CLI](https://ui.shadcn.com/docs/cli) с основой `base` и стилем `base-nova`. Добавить компонент:

```sh
cd frontend
pnpm exec shadcn add tooltip
```

## Проверки

Из корня можно запустить все проверки вместе с подготовкой assets и bindings:

```sh
wails3 task check
```

Или отдельно:

```sh
pnpm --dir frontend check
pnpm --dir frontend test:coverage
pnpm --dir frontend build
go test ./...
go vet ./...
```

На чистом checkout перед `go test ./...` нужна сборка фронтенда: `main.go` встраивает `frontend/dist`. Отчёт покрытия фронтенда — `frontend/coverage/index.html`.

Для разработки есть `format`, `lint:fix` и `test:watch`. [Oxlint](https://oxc.rs/docs/guide/usage/linter/config) включает категории correctness/suspicious, React Hooks, accessibility, TypeScript, Vitest и [type-aware проверки](https://oxc.rs/docs/guide/usage/linter/type-aware), в том числе небезопасных типов и необработанных Promise. Предупреждения завершают проверку ошибкой. Oxfmt отвечает за форматирование; ESLint и Prettier не требуются. Generated bindings исключены из линтинга и форматирования. Узкие исключения в коде объясняют SVG-роли и гарантии Go-контракта.

Тесты проверяют геометрию, клавиатурный выбор, подсчёт прогресса, успешные и неудачные операции, черновики и изменение структуры схемы. Go-тесты проверяют валидацию, нормализацию, запись и импорт/экспорт, повреждённые и слишком большие файлы, отмену диалогов и сохранность данных при ошибках.
